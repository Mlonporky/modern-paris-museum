# 《光线照进现代巴黎》线上美术馆设计说明

## 1. 项目目标

建立一个面向普通公众、同时能服务中学生和艺术史初学者的中文线上美术馆。第一期展览以“19世纪印象派与现代城市生活”为主题，不只陈列作品，还要解释作品与当时的城市建设、工业化、社会阶层、消费文化和艺术市场之间的关系。

这个项目同时承担学习任务。开发过程必须采用小步迭代：先解释目标，再进行少量修改，然后查看网页效果和代码差异，最后用非技术语言复盘。用户不需要安装或操作 VS Code；Codex 直接在项目目录中修改文件，用户通过 inline diff 审阅变化。

## 2. 目标受众与成功标准

### 目标受众

- 主要受众：对艺术和历史感兴趣、但没有专业背景的普通公众。
- 次要受众：中学生、大学生和艺术史初学者。
- 内容语言：第一版只使用简体中文。

### 第一版成功标准

- 访客能够在一个连续页面中完成整场展览阅读。
- 访客能够说出至少两项促成印象派现代生活题材的社会或经济变化。
- 四幅核心作品均包含艺术观察、历史社会背景和经济生活三个解释角度。
- 页面在电脑和手机上均可清楚阅读和操作。
- 所有画作都标明收藏机构、图片来源链接和版权或开放使用说明。
- 三道小测验能够即时反馈答案并解释原因。
- 项目能够从 GitHub 仓库自动构建并发布到 GitHub Pages。
- 新增作品时，只需新增内容文件，不需要复制整段页面结构。

## 3. 第一版范围

第一版是单页专题展览，不建立账号、评论、搜索、购票、在线支付、后台管理系统或远程数据库。页面按以下叙事顺序展开：

1. 封面与策展引言：为什么印象派会在19世纪巴黎出现。
2. 历史时间线：工业化、铁路扩张、奥斯曼改造、百货商店和印象派展览等关键节点。
3. 城市为何改变：用短篇文化杂志式文章连接政治、人口、基础设施和资本。
4. 四幅作品专题：以作品为入口观察现代城市生活。
5. 艺术市场：画商、私人收藏者和独立展览如何改变艺术生产与销售。
6. 三道互动小测验：帮助访客回顾关键概念。
7. 资料与图片来源：提供可追溯的博物馆和历史资料链接。

四幅核心作品为：

1. 古斯塔夫·卡耶博特《巴黎街道；雨天》（1877）：奥斯曼改造、宽阔街道与现代都市观看方式。
2. 克洛德·莫奈《圣拉扎尔火车站》（1877）：铁路、工业、蒸汽和速度。
3. 皮埃尔-奥古斯特·雷诺阿《煎饼磨坊的舞会》（1876）：城市娱乐、新兴消费与阶层混合。
4. 爱德华·马奈《女神游乐厅的吧台》（1882）：服务劳动、商品展示、性别和阶层目光。

页面会明确说明马奈是印象派的重要先驱和同时代艺术家，但没有参加印象派独立展览，避免把艺术史关系简单化。

## 4. 内容架构

项目使用 Astro 6 的构建时 Content Collections。这里的“内容数据库”是保存在 Git 仓库中的结构化 Markdown 和 JSON 文件，不需要数据库服务器，也不收集访客数据。

### `artworks` collection

每幅作品对应一个 Markdown 文件。文件顶部的结构化字段保存：

- `title`：中文标题。
- `originalTitle`：原文标题，可选。
- `artist`：艺术家中文名。
- `artistOriginal`：艺术家原文名。
- `year`：创作年份。
- `theme`：该章节的社会主题。
- `order`：页面展示顺序。
- `image`：项目中的图片路径。
- `imageAlt`：为看不到图片的访客提供的中文描述。
- `museum`：收藏机构。
- `sourceUrl`：机构页面或权威来源。
- `rightsNote`：图片版权或开放使用说明。
- `timelineIds`：与作品相关的时间线事件编号。

Markdown 正文统一包含三个二级段落：“看见什么”“时代发生了什么”“钱与生活如何改变”。统一结构既方便访客形成阅读习惯，也便于后续扩展和质量检查。

### `timeline` collection

时间线使用一个 JSON 文件，通过 Astro 的 `file()` loader 读取。每个事件包含唯一 `id`、时间标签、标题、简短说明和分类。分类限定为“城市”“工业”“社会”“艺术市场”，用于视觉标签和后续筛选。

### Schema 验证

`src/content.config.ts` 使用 Astro 的 Zod schema 定义必填字段、字段类型和允许值。构建时若作品缺少年份、替代文字、来源或版权说明，构建必须失败，防止不完整内容上线。

## 5. 技术架构与文件边界

项目采用 Astro 静态站点，不引入 React、Vue 或远程 CMS。只在小测验和必要的导航交互中使用少量浏览器 JavaScript。

```text
src/
├─ components/
│  ├─ Header.astro
│  ├─ Timeline.astro
│  ├─ ArtworkSection.astro
│  ├─ MarketEssay.astro
│  ├─ Quiz.astro
│  └─ Sources.astro
├─ data/
│  ├─ artworks/
│  │  ├─ paris-street-rainy-day.md
│  │  ├─ gare-saint-lazare.md
│  │  ├─ moulin-de-la-galette.md
│  │  └─ bar-at-the-folies-bergere.md
│  └─ timeline.json
├─ layouts/
│  └─ BaseLayout.astro
├─ pages/
│  └─ index.astro
├─ styles/
│  └─ global.css
└─ content.config.ts
public/
└─ images/
```

各单元职责如下：

- `index.astro` 查询内容 collections，按 `order` 排序，再把数据交给页面组件。
- `BaseLayout.astro` 负责 HTML 文档基础、页面元数据、字体和全站外壳。
- `ArtworkSection.astro` 只负责呈现一幅作品及其三个解释角度，不保存具体作品文案。
- `Timeline.astro` 只负责时间线的语义结构和展示。
- `Quiz.astro` 保存三道题的交互逻辑，并为没有 JavaScript 的访客保留可阅读的题目内容。
- `global.css` 负责设计系统、响应式布局、焦点状态和减少动画设置。

该边界确保内容与版式分离：编辑史料不需要修改组件，修改版式也不需要重写作品资料。

## 6. 页面视觉与交互

视觉方向是“内容丰富的文化杂志”，而不是极简画廊。基础风格使用米白纸张色、深墨文字、灰蓝与暗红强调色。标题使用具有编辑感的衬线字体，正文优先选择系统可用的中文字体，避免依赖加载缓慢或授权不清的字体文件。

页面特征包括：

- 封面使用一幅核心作品的局部图与醒目策展标题。
- 顶部目录可跳转到时间线、四幅作品、艺术市场、小测验和资料来源。
- 时间线在宽屏上横向组织，在窄屏上转为纵向阅读。
- 作品章节交替使用图片与文字布局，形成杂志翻页般的节奏。
- 三种解释角度使用稳定的栏目标题，不隐藏关键内容。
- 动画仅用于轻微的进入提示，并遵守访客的“减少动态效果”系统设置。
- 小测验提交后显示正确与否、正确答案和一句解释，不记录分数或个人信息。

## 7. 数据流与错误处理

构建流程为：内容文件进入 Content Collections，schema 先验证字段，`index.astro` 再查询和排序，组件将数据渲染成静态 HTML，Astro 最后输出到 `dist/`。

错误处理原则如下：

- 内容字段缺失或格式错误：构建失败，并显示对应内容文件和字段。
- 本地图片缺失：自动化检查和人工页面检查必须发现问题，发布前修复。
- 外部来源链接失效：不影响页面主体渲染，但上线前检查链接并在 README 中记录核查日期。
- JavaScript 被禁用：展览正文、时间线和题目仍可阅读；只有即时答题反馈不可用。
- GitHub Pages 构建失败：通过 GitHub Actions 日志定位失败的安装、构建或发布步骤，不手工上传 `dist/`。

## 8. 可访问性与内容伦理

- 页面使用语义化标题层级、`main`、`nav`、`section` 和 `figure`。
- 所有交互可以使用键盘完成，并提供清晰焦点样式。
- 正文和背景达到可读的颜色对比度，正文不使用过小字号。
- 每幅作品提供描述画面信息的中文替代文字，而不是只重复作品名。
- 历史解释区分事实、策展概括和存在争议的观点。
- 作品与图片来源优先采用收藏机构和公共领域开放资源；每幅图片单独记录权利状态。
- 不把马奈错误标记为参加印象派展览的成员。

## 9. 验证与测试

每个实现阶段都执行与风险相称的检查：

- 运行 Astro 类型和内容检查，确认 collection schema 通过。
- 运行生产构建，确认 `dist/` 能完整生成。
- 检查电脑宽屏、普通笔记本和手机窄屏布局。
- 使用键盘走完整个目录和小测验流程。
- 检查四幅作品的图片、替代文字、来源链接和权利说明。
- 人工完成三道题，分别验证正确和错误反馈。
- 发布后访问 GitHub Pages 公网地址，检查路径、图片和页内链接。

## 10. Git 与发布学习流程

Git 历史使用小而有意义的提交。每次提交前解释三件事：改了什么、为什么改、如何验证。第一阶段的建议提交顺序为：

1. 保存经批准的设计说明。
2. 初始化 Astro 与内容 collections 骨架。
3. 建立全站版式和视觉变量。
4. 添加时间线内容与组件。
5. 逐步添加四幅作品内容与展示组件。
6. 添加艺术市场章节和小测验。
7. 完成来源、可访问性和响应式检查。
8. 添加 GitHub Pages 自动发布流程。

项目使用 `main` 作为默认分支，使用 npm 和提交到仓库的 lockfile 保证安装一致。GitHub Pages 通过官方 Astro GitHub Action 构建和发布；每次推送到 `main` 后自动更新网站。GitHub 身份只在确认用户名和邮箱后设置，不擅自修改全局 Git 配置。

## 11. 第一版明确不做的内容

- 不建立真实数据库服务器或用户账户。
- 不建立内容管理后台。
- 不加入中英双语切换。
- 不加入站内搜索、收藏、评论和社交分享统计。
- 不购买域名；先使用 GitHub Pages 提供的网址。
- 不一次扩展到完整印象派史或多个展览。

这些功能可以在第一版成功发布并完成复盘后，作为独立的小项目逐项设计。
